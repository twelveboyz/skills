# 慢因七类（A–G）

逐类过一遍，每类给四件套：**信号 → 证据（文件:行号 或 步骤号）→ 根因（机制层）→ 修复**。写不出证据的不进报告。

## A 文档与实现漂移

文档声明的参数、路径、格式、步骤与实现不符，照文档敲必失败再重试。

信号：文档里出现 `--flag` 而 `argparse` 没有；文档写的产物路径与脚本 `PROJECT_DIR` 拼出来的不同；文档说「会自动补 `#!`」而代码 `raise`；同一天内改过多次的 SKILL.md 留了多个 `.bak`。

查证：`--help` 或 `main()` 里的 `add_argument` 是参数唯一事实源，逐字比对。

## B 参数歧义

同一概念多个名字、别名与真实 ID 之间缺显式映射、互斥参数不在解析期拒绝、枚举大小写不一致、区间语法边界未声明。

**判据：一次调用是否可能「猜错但仍被接受」。**

信号：用户口头名（东莞/广州3）与平台 region 码（`N020-GD-GZNJ04`）两套命名并存且表里只收一套；`gz3` 被显示成「东莞」而平台里它叫广州3；池号给错时接口不报 404 只返回 0 条，报错文案是「没有名称包含这些关键字的主机」，把「池错」与「关键字错」混成一种故障。

## C 串行闸门过多

只读步骤后仍弹确认、只读与写耦合在同一入口无法单独重跑、用户已说「这类别问」但流程仍写死确认。

信号：一个只读的 preview 之后紧接 `ask_user_question`；用户原话里出现过「为什么要跟我确认/下次别弹」。

## D 失败恢复粒度粗

批量中单点失败导致整轮重跑、无幂等、瞬时错误与参数错误不区分、单批规模只在示例数据上验证过。

信号：28 台机器一次性塞进一个 `serverIds` 数组，接口回「云主机ID列表不能超过20」，改分批后第二批又撞瞬时错误，只能人工重跑整个 run 且第 1 批会重复执行。

## E 静默降级

首选资源缺失时改用次选且退出码仍成功、结果看似成功实为空或错、降级只在日志留一行。

信号：`read_token()` 静默回落到第一个存在的 token 文件而不提示命中哪个；缺 `tools/` 时自动借用 PATH 里的同名程序，出来的 xlsx 申请人为空、退出码 0；生成脚本把常量标签和实测字段打在同一张表里，28 行的值完全相同看着像「逐台实测」。

## F 往返与体量

本可合并的串行步骤被拆成多次调用、stdout 直接吐全量明细、摘要与数据不分层、看结果必须重发命令。

信号：「读文件 → ls 目录 → 跑工具 → 跑 dry-run → 弹确认 → 真跑 → ls 核对」七次串行调用，实际计算量 3 秒，人花了 2 分钟。

## G 不确定性引入的抖动

依赖顺序不保证的并发、随机化、缓存未命中、外部限流无退避，导致同样任务耗时方差大。

**判据：同一任务跑三次，N_call 或 T_wall 差异显著且无解释。**
