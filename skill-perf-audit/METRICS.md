# 指标与基线

每个 skill 都用这套指标，不另造。

| 指标 | 定义 | 采集方式 |
|---|---|---|
| N_call | 完成一次典型任务的工具调用总次数 | 数 trace；无 trace 自己跑一遍记步 |
| N_gate | 中途需要用户回复才能继续的次数 | 数交互点 |
| N_read | agent 为拼出正确调用需要读的文件数 | 数依赖文档与 `--help` |
| N_retry | 一次典型失败造成的额外调用数 | 构造失败后实测 |
| N_bytes | 单次调用的 stdout 体量（行数或 KB） | 直接量 |
| T_wall | 端到端墙钟时间 | 有日志用日志；无日志用 `N_call × 单次往返` 并标注「估算」 |

## 目标值（按 skill 性质声明，不声明视为无效）

| skill 性质 | N_call | N_gate | N_read |
|---|---|---|---|
| 例行只读任务 | ≤ 2 | = 0 | ≤ 1 |
| 例行写操作任务 | ≤ 2 | ≤ 1 | ≤ 1 |

任意任务：`N_retry ≤ 1` —— 失败只重发失败单元，不整轮重来。

`N_bytes` 与 `T_wall` 没有通用上限：以本 skill 实测基线为分母报改善比例，报绝对值时写明依据。

## 采集提示

- `N_read` 数的是**拼出正确调用**所需的文件，不是 agent 实际读过的文件。读了 5 个才拼对，下限就是 5。
- `N_gate` 只数**必要性**存疑的等待。用户主动指定的确认点照数，但不计入冗余。
- `T_wall` 是估算时必须标注，否则不写进基线表。
- 同一任务跑三次取 N_call 与 T_wall 的离散度，是第 3 步 G 类（抖动）的唯一证据来源。
