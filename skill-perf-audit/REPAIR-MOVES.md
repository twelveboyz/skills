# 改造手法

每个手法写清三件事才能动手：**改哪个入口/函数、加哪个参数、删哪段文档**。

## 合并

- **串行步骤合成单入口单命令** — 把 N 次调用压成一次出结果。适用 F 类；判据是中间产物没有被第二步之外的东西需要，合并后仍能单独重跑。
- **stdout 分层** — 摘要与确认表走 stdout，明细落文件并提供只读回放入口。适用 F 类。

## 拆开

- **只读入口与写入入口分离，共享同一份中间产物**（plan / 缓存文件） — 适用 C 类。只读入口可反复重跑，不产生副作用。
- **文档骨架只留三样**：一条黄金命令、参数真值表、三类失败的处理方式。其余下沉为被指针引用的参考。

## 拒绝歧义

- **解析期即拒绝**：互斥参数、未知别名、非法枚举在 `argparse` 阶段报错，不进入执行。
- **归一化打印**：确认表里给「输入词 → 归一化值 → 真实 ID」三元组。
- **单源别名表**：同一实体的两套命名（业务名 / 平台码）都收进同一张常量表，显示时并列（`东莞/广州3`），不并列就会每次都对不上。
- **故障二分**：命中 0 条时把「各池查到 N 台」的证据一起打出来，让「池选错」与「关键字错」在输出里可区分。

## 恢复

- **批次级重试 + 已完成单元落盘**，支持断点续跑。适用 D 类。
- **瞬时错误白名单原地重试 + 退避**，参数类错误立即失败并记入 `failedUnits`。
- **单批上限在真实规模上验证**，不按示例数据写死；接口上限与业务规则不一致时问用户。

## 浮现失败

- **降级改显式失败**，或降级结果在最终摘要里打醒目标记（退出码 0 但摘要必须喊出来）。
- **常量与实测分离**：脚本里写死的标签不进「实测」措辞列；同一批值全相同时先怀疑它是常量。

## 固化为机制

- **文档由代码生成**：参数真值表直接从 `--help` / 常量导出，不手抄。
- **自检入口**：一条 `--selftest` 校验文档与实现一致，纳入第 6 步回归用例。
